This page explains how to run Happier inside a container (for example: a remote VM or a disposable “dev box”) and authenticate it **from your local machine**.

## Dev box image

Happiest publishes no dev box image, so you build it yourself from this repository. The build downloads a released `happiest` CLI archive from the GitHub Releases of `ErikaAlk/happiest`, verifies its checksum and minisign signature, and installs it into the image. Run it from the repository root, because the Dockerfile copies the download script and the signing public key from the repository:

```bash
docker build -f docker/dev-box/Dockerfile \
  --build-arg HAPPIER_DEVBOX_CLI_RELEASE_TAG=cli-v0.1.0 \
  --build-arg HAPPIER_DEVBOX_CLI_VERSION=0.1.0 \
  -t happiest-dev-box .
```

The build arguments:

| Argument | Meaning |
| --- | --- |
| `HAPPIER_DEVBOX_CLI_RELEASE_TAG` | The versioned CLI release tag to download, for example `cli-v0.1.0`. Required. |
| `HAPPIER_DEVBOX_CLI_VERSION` | That release's version, for example `0.1.0`. Required. |
| `HAPPIER_RELEASE_BASE_URL` | Where the release assets are downloaded from. Defaults to `https://github.com/ErikaAlk/happiest/releases/download`. |

Pick a version that exists on the [releases page](https://github.com/ErikaAlk/happiest/releases). The image builds for `linux/amd64` and `linux/arm64`, the two Linux targets the CLI is released for.

The image includes:

- the released `happiest` CLI binary
- optional provider CLIs, installed on first boot via `happiest install provider`

The image does not include a source checkout or `hstack`; it is meant for using Happier from a container, not developing Happier itself.

Note: “dev box” is our Docker image name — it’s not tied to any specific editor “devcontainer” feature.

### Optional: install provider CLIs on first boot

Set `HAPPIER_PROVIDER_CLIS` to install provider CLIs through the Happier CLI:

```bash
docker run --rm -it \
  -e HAPPIER_PROVIDER_CLIS=claude,codex \
  happiest-dev-box
```

Supported values today: `claude`, `codex`.

## Recommended: persist Happier state

Persist `~/.happiest` so credentials, machine IDs, logs, etc. survive container restarts. The container runs as the user `happier`, so its home is `/home/happier`:

```bash
docker run --rm -it \
  -v happiest-home:/home/happier/.happiest \
  happiest-dev-box
```

## Pair a remote container/host from your local CLI (no web UI)

If your **local** machine is already authenticated (`happiest auth status` is OK), you can pair a **remote** host/container over SSH:

```bash
happiest auth pair-remote --ssh user@host
```

What this does:

1. Runs `happiest auth request --json` on the remote host.
2. Approves the request locally using your existing token (the local token is **not** sent to the remote host).
3. Runs `happiest auth wait --public-key ... --json` on the remote host to claim the request and write credentials.

Use `--json` when scripting. If your active relay URL is loopback-only (`localhost` / `127.0.0.1`), interactive mode offers reachable addresses for this computer. In scripts, pass `--server-url-for-remote <url>` with the address the remote host can use to reach this computer's relay (`--remote-server-url` is still accepted as a legacy alias).

### Manual (scriptable) alternative

If you want to integrate with custom orchestration:

1) On the remote host:

```bash
happiest auth request --json
```

2) On your local machine (authenticated):

```bash
happiest auth approve --public-key <publicKey> --json
```

3) Back on the remote host:

```bash
happiest auth wait --public-key <publicKey> --json
```
