This page documents `hstack remote server setup`, a workflow to provision a **remote machine** (VPS, home server, dev box) over SSH:

- runs `happiest relay host install --ssh` against the remote host, which installs the server runtime from the GitHub Releases of `ErikaAlk/happiest`
- installs the server runtime as a managed service (default: **user** mode)

If you want to provision a remote machine for **CLI + daemon** usage (pairing/auth included), see: [Remote daemon setup (SSH)](/hstack/remote-daemon).

## Quickstart

```bash
hstack remote server setup --ssh user@host
```

Default behavior:

- uses the **stable** channel, the only channel Happiest publishes
- installs the self-host service in **user** mode
- uses the self-host defaults (SQLite, local files, `PORT=3015`)

## Release channel

Happiest publishes stable releases only, so setup always installs the stable server runtime. `--stable` (or `--channel stable`) states it explicitly:

```bash
hstack remote server setup --ssh user@host --stable
```

## User vs system service

User service (default):

```bash
hstack remote server setup --ssh user@host --mode user
```

System service:

```bash
hstack remote server setup --ssh user@host --mode system
```

Notes:

- `--mode system` runs the remote install with `sudo -E` and may prompt for a password, depending on the host’s sudo policy.
- User mode is recommended unless you specifically need system-wide service semantics.

## Override server configuration (env)

You can pass repeated `--env KEY=VALUE` flags. These become overrides in the generated `server.env` on the remote host.

Example: change the listen port:

```bash
hstack remote server setup --ssh user@host \
  --env PORT=3999
```

Example: use Postgres instead of SQLite:

```bash
hstack remote server setup --ssh user@host \
  --env HAPPIER_DB_PROVIDER=postgres \
  --env DATABASE_URL=postgresql://user:pass@db:5432/happier
```

Tip: for the full server env surface, see [Environment variables](/self-hosting/env).

## Auto-update scheduling (daily window)

Remote server setup does not schedule automatic updates. The `hstack self-host config set` scheduler is not available on the remote host, because hstack is not released and setup does not install it there.

## Requirements

- SSH access to the remote host (`ssh user@host`)
- Remote host has `bash` and `curl`
- Remote host must run Linux on x64 or arm64, the platforms Happiest releases the server runtime for. Happiest publishes no macOS binaries, and Windows hosts are not supported for this SSH flow.
