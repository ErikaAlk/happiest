This guide explains how to run a Happier relay on **Proxmox VE** in a Debian LXC container. Happiest has no Proxmox helper script, so you create the container, install the relay with the managed install, and add remote access yourself.

## What you get

- A dedicated **Debian LXC container** running Happier Server (light flavor with SQLite) as the systemd *system* service `happiest-server`.
- The **web UI** served from the same container.
- **Autostart** at boot through that service.
- Optional **Tailscale** for remote access + HTTPS (recommended for phone access).

## What you need first

- A Proxmox VE host where you can create LXC containers.
- A Debian 12 container template. The relay server is published for Linux x64 and Linux arm64, so the container must match one of them.

## Install

1. In the Proxmox web UI, create a Debian 12 LXC container with network access, and start it.
2. On the **Proxmox host shell**, enter the container:
   - `pct enter <CTID>`
3. Inside the container, install the Happiest CLI. A minimal Debian template has no `curl`, so install it first:

   ```bash
   apt-get update && apt-get install -y curl ca-certificates
   curl -fsSL https://github.com/ErikaAlk/happiest/releases/download/cli-stable/install.sh | bash
   ```

4. Still inside the container, install the relay as a system service:

   ```bash
   happiest relay host install --mode system
   ```

A managed install listens on port 3015, on the loopback address unless you pass `--lan` (a LAN or Tailscale address), `--expose` (all interfaces) or `--host <ip>` to `happiest relay host install`. See [Self-host runtime](/self-hosting/self-host-runtime) for what the managed install owns.

Check that it is running:

```bash
happiest relay host status
```

Local access, when you bound the relay to a LAN address or all interfaces:

- `http://<container-ip>:3015` (LAN)

If you serve the relay only through **Tailscale** (below), it stays on the loopback address and is not reachable from your LAN IP. In that case, use your Tailscale **HTTPS** URL instead.

## Quick start

1. Install the relay in a container (above).
2. Choose a remote access option:
   - **Tailscale** (recommended) if you want an HTTPS URL without opening ports.
   - **Reverse proxy** if you already have Caddy/Nginx/Traefik.
3. On the computer where you want to run the daemon/terminal:
   - `happiest server add --server-url https://<your-server-url> --use`
   - `happiest auth login --method=mobile`
4. On your phone, scan the QR code (or open the deep link). The app will prompt to switch servers (if needed), then you can sign in/create an account and approve the terminal connection.
5. To run the daemon inside the container, see [Run a daemon in the container](#run-a-daemon-in-the-container).

## After install: recommended onboarding flow

Happier has two separate “things to connect”:

- Your **app/web UI** needs to be configured to talk to **your server**
- Your **terminal/daemon** needs to be connected to **your account on that server**

The relay install **does not** authenticate for you. Use the commands and links below for the full flow.

### 1) Ensure you have a public HTTPS URL (remote access)

If you only access Happier from your LAN, plain HTTP can work.

For remote access (phone / outside your LAN), the web UI requires **HTTPS** (secure context). Use one of:

- **Tailscale Serve** (recommended): easiest end-to-end HTTPS
- **Reverse proxy** (Caddy / Nginx / Traefik): terminate TLS and proxy to the container

Tell the relay its public HTTPS URL by adding these lines to `/etc/happiest/server.env` inside the container:

- `HAPPIER_PUBLIC_SERVER_URL=https://<your-domain>` (canonical/share URL used in QR/deep links)
- `HAPPIER_WEBAPP_URL=https://<your-domain>` (the relay serves the web UI, so this is your own domain)

Then restart the service: `systemctl restart happiest-server`.

#### Advanced: reverse proxy (Caddy / Nginx)

For a reverse proxy setup, you typically terminate TLS on your proxy and forward to:

- `http://<container-ip>:3015`

The relay must be bound to an address the proxy can reach, so install it with `--lan` or `--expose` (see [Install](#install)) when the proxy runs on another machine. If the proxy runs inside the same container, the default loopback address is enough, and you forward to `http://127.0.0.1:3015`.

Make sure your proxy supports **WebSockets** and forwards the usual “real URL” headers:

- `Host`
- `X-Forwarded-Proto`
- `X-Forwarded-Host`
- `X-Forwarded-For`

Also make sure the relay knows its public URL (for correct deep links/QR codes): `HAPPIER_PUBLIC_SERVER_URL=https://<your-domain>` in `/etc/happiest/server.env`, then `systemctl restart happiest-server`.

**Caddy** (recommended for simplest HTTPS)

`Caddyfile`:

```
happiest.example.com {
  reverse_proxy http://<container-ip>:3015
}
```

If you’re running Caddy on the Proxmox host or another machine, replace `<container-ip>` with your container’s LAN IP.

**Nginx** (manual config)

Server block snippet:

```nginx
server {
  listen 443 ssl http2;
  server_name happiest.example.com;

  # TLS config omitted (use certbot, or your existing TLS setup)

  location / {
    proxy_pass http://<container-ip>:3015;
    proxy_http_version 1.1;

    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Host $host;

    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
  }
}
```

If you use a UI-driven reverse proxy (e.g. Nginx Proxy Manager / Traefik), make sure “WebSocket support” is enabled and the upstream is `http://<container-ip>:3015`.

### 2) Configure your app/web UI to use your server

In most cases you don’t need a separate “configure server” step anymore: terminal connect links include `server=...`, so the app/web UI can safely prompt you to switch servers before you approve the connection.

If you want to add/switch servers manually in the app:

- Open **Settings → Relays** and add your relay URL.

The relay serves the web UI itself, so you can also open your relay URL in a browser.

### 3) Connect the terminal/daemon

Continue following the `happiest auth login` output:

- If you’re using the mobile app: scan the QR code / open the mobile deep link
- If you’re using the web app: open the URL in a browser where you’re signed in

Because the link includes the server URL, the app/web UI can safely prompt you to switch servers (if needed) before approving the connection.

## Run a daemon in the container

The relay install above runs only the server. To also run a daemon inside the container (so sessions can execute there), sign in from the container and install the daemon service, as described in [Daemon](/apps/daemon):

```bash
happiest server add --server-url https://<your-server-url> --use
happiest auth login
happiest daemon install
```

After login completes, you can check or restart the daemon service with `happiest daemon service status` and `happiest daemon service restart`.

## Using Happier from another machine (common setup)

If you only installed the relay on Proxmox, you’ll typically run the **daemon/terminal** from your laptop/desktop and point it at your Proxmox server.

On your laptop/desktop:

- Save and switch to your self-hosted server:
  - `happiest server add --server-url https://<your-server-url> --use`
- Then connect your terminal/daemon:
  - `happiest auth login`

This persists the server URL locally, then prints:

- “Connect terminal” links (mobile QR/deep link + web URL) so you can approve the machine connection

If you need to explicitly configure/switch servers in the app/web UI (rarely needed), run:

- `happiest auth login --print-configure-links`

For ongoing profile switching and multi-server usage, see [Features → Multi-server](/accounts/multi-server).

## Tailscale

Tailscale gives the relay an HTTPS URL inside your tailnet without opening ports. Install Tailscale in the container by following Tailscale’s own instructions, then enroll the container and publish the relay with Tailscale Serve.

Enrollment depends on your tailnet policy:

- **Interactive:** `tailscale up` prints a login URL to open in a browser.
- **Pre-auth key:** `tailscale up --authkey=<key>`. Use an ephemeral, one-time key when possible.

Commands (inside the container):

```bash
tailscale up
tailscale serve --bg http://127.0.0.1:3015
tailscale serve status
```

Then set `HAPPIER_PUBLIC_SERVER_URL=https://<machine>.<tailnet>.ts.net` in `/etc/happiest/server.env` and run `systemctl restart happiest-server`.

## HTTPS guidance (important)

For remote usage, the Happier web UI needs **HTTPS** (secure context). Typical setups:

- **Tailscale Serve** (easiest): gives you an HTTPS URL without opening ports.
- **Reverse proxy**: terminate TLS on your network edge and proxy to `http://<container-ip>:3015` (ensure WebSockets are supported).

## Post-install: common commands

Enter the container from the Proxmox host:

- `pct enter <CTID>`

Relay service:

- `happiest relay host status`
- `systemctl status happiest-server`
- `journalctl -u happiest-server -f`

Daemon service (if you installed one in the container):

- `happiest daemon service status`
- `happiest daemon service restart`
- `happiest auth status`

## Updating

Run these inside the container:

- `happiest relay host install --mode system` (installs the latest stable relay release in place)
- `happiest self update` (updates the Happiest CLI)
