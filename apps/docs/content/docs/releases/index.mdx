title: Release channels
description: What Happiest publishes, where it is published, and how a change reaches you.

Happiest publishes one channel, **stable**, as
[GitHub Releases](https://github.com/ErikaAlk/happiest/releases) on
`ErikaAlk/happiest`. The CLI, the relay server and the desktop app all follow
that line, so there is one command to remember: `happiest`.

## What is published

| Piece | Platforms | Rolling tag | Versioned tag |
| --- | --- | --- | --- |
| **CLI** | Windows x64, Linux x64, Linux arm64 | `cli-stable` | `cli-v<version>` |
| **Relay server** | Windows x64, Linux x64, Linux arm64 | `server-stable` | `server-v<version>` |
| **Desktop app** | Windows x64, Linux x64 | `ui-desktop-stable` | `ui-desktop-v<version>` |

Versions start at `0.1.0`. A rolling tag always points at the newest release of
its piece. A versioned tag stays on the release it names, so use it when you
want an exact version.

<Callout type="warn">
  The Windows desktop installer is not code-signed. Windows can show an
  unknown-publisher warning when you run it.
</Callout>

There are no macOS builds. Happiest does not publish preview or dev releases,
npm packages, a Homebrew formula, Docker images or a hosted deployment, and
hstack is not released for now. A relay server in a container is built locally
from the repository `Dockerfile`; [Docker](/self-hosting/docker) covers the
build.

## How a change reaches you

Stable releases are published from the repository's `main` branch. Each piece
has its own versioned tag, so a new CLI version and a new desktop version are
separate releases.

The CLI updates itself from those releases with `happiest self update`, and the
desktop app prompts for updates from its own release. A relay server updates
when you rerun its installer or rebuild its image. [Updates](/releases/updates)
lists every install method and what it asks of you.
